6. EXACT REASON /ready WAS 503 BEFORE

There were two independent readiness defects:

A. Redis:
- Redis was unavailable on localhost:6379.
- The readiness function always required redis even in development, despite AppConfig.redisRequired being false outside production.

B. Provider mismatch:
- The readiness function checked providerRegistry.get("binance").adapter.healthcheck().
- Binance was disabled.
- The active real provider was Deriv through LiveProviderBridge.
- Therefore providerReady was false even while Deriv was receiving data.

7. FIX APPLIED

[src/server.ts]
- Redis is required by /ready only when config.redisRequired=true.
- Active provider readiness uses Deriv LiveProviderBridge when configured.
- Response now exposes redisRequired, provider, and providerState.
- No Redis success is fabricated.
- Binance was not enabled.
